## 第六天：GitHub 项目筛选与阅读

今天完成了 `00-学习方法论 / 05-GitHub项目精选-入门导航` 的核心学习。目标不是批量收藏仓库，而是学会判断一个项目是否值得投入时间。

## 一、代表性项目

今天使用 `microsoft/Web-Dev-For-Beginners` 进行实际观察。

- 项目面向 Web 初学者
- 包含 24 节课程
- 课程不仅讲 HTML、CSS 和 JavaScript，还包含测验、讲解、实践、挑战与作业
- 当前仍有近期提交，说明项目持续维护

## 二、阅读 GitHub 项目的顺序

```text
README → Issues → Pull requests
```

- `README`：了解项目是什么、面向谁、如何使用
- `Issues`：了解项目的 Bug、限制、维护状态和社区反馈
- `Pull requests`：了解问题如何被修改、审核和合并

今天阅读了一个修复页面 404 的已合并 PR。该 PR 修改范围较小，只调整了相关翻译 README，并在审核后合并。由此理解到高质量 PR 通常具备问题明确、修改集中、容易审核等特点。

## 三、判断项目质量

不能只看 Star 数。判断一个项目是否适合当前学习，应综合考虑：

- 是否符合当前学习阶段
- README 是否清楚
- 最近是否仍有提交
- Issues 是否有标签和回复
- PR 是否经过检查或审核
- 是否能产生实际练习成果

一个 3000 Star、持续维护、文档清楚的项目，可能比一个 10 万 Star、长期无人维护的项目更适合学习。

## 四、GitHub 搜索过滤

今天练习了：

```text
language:javascript stars:>1000 topic:beginner
```

- `language:javascript`：主要语言为 JavaScript
- `stars:>1000`：至少 1000 Star
- `topic:beginner`：带有初学者主题

过滤器可以减少无关结果，但筛选后仍需要检查活跃度、文档和项目难度。

- 等正式进入 HTML、CSS 和 JavaScript 章节时，再从该仓库选择一节实际完成
