## 第五天：Git 分支、SSH 与 PR

今天继续学习 `Git 与 GitHub 入门`，完成了分支合并、SSH 身份验证、GitHub CLI 登录和第一次完整的 PR 流程。

## 一、分支与合并

- 使用 `git switch main` 切换回主分支
- 使用 `git merge practice/git-branch` 将练习分支合并到 `main`
- 理解 `Fast-forward` 是主分支指针直接向前移动
- 使用 `git branch -d` 安全删除已经合并的本地分支
- 使用 `git fetch --prune` 清理已经删除的远程分支引用

分支的主要用途是在不影响稳定主线的情况下独立开发、修复或试验。多人可以在不同分支开发，经过测试和 PR 审核后再选择合适的方案合并到 `main`。

## 二、SSH 身份验证

- 认识 HTTPS 和 SSH 两种 GitHub 连接方式
- 确认电脑以前已经配置过 RSA SSH key
- 理解不同 SSH key 通常代表不同设备或开发环境，不代表不同仓库
- 使用 `ssh -T git@github.com` 成功验证 GitHub 身份
- 将仓库远程地址从 HTTPS 改为 SSH

SSH 使用公钥和私钥验证身份。公钥可以上传到 GitHub，私钥必须保留在本机，不能分享。

## 三、GitHub CLI 与 PR

- 安装 GitHub CLI：`gh`
- 使用 `gh auth login` 登录 GitHub
- 从 `main` 创建 `docs/day-five-notes` 分支
- 在分支中新增今天的学习笔记并提交
- 将分支推送到 GitHub
- 使用 `gh pr create --fill` 创建 PR
- 在 GitHub 检查 `Files changed` 后合并 PR
- 切回 `main` 并通过 `git pull` 同步合并结果
- 删除已经完成使命的本地和远程分支引用

完整 PR 流程：

```text
创建分支 → 修改 → add → commit → push → 创建 PR
→ 审核变化 → 合并 → 切回 main → pull → 删除分支
```

## 四、今天掌握的关键区别

- `git init`：将一个本地项目初始化为 Git 仓库
- `git clone`：将已有的远程仓库及其历史下载到本地
- `Fork`：在 GitHub 上把别人的仓库复制到自己的账号
- `Clone`：把 GitHub 仓库下载到电脑
- `Commit`：在本地创建版本快照
- `Push`：把本地提交上传到远程仓库
- `PR`：请求将一个分支的修改审核并合并到目标分支

四个区域对应的核心命令：

```text
工作区 --git add--> 暂存区 --git commit--> 本地仓库
       --git push--> GitHub 远程仓库
```
