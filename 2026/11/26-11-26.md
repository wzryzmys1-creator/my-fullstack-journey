## 一、费曼学习法

费曼学习法的核心流程：

```text
尝试用简单的话解释
→ 找出讲不清或理解错误的地方
→ 只补这个知识漏洞
→ 关掉资料重新解释
```

### Git 分支

核心理解：Git 分支通过隔离修改来保护稳定主线，而不是消灭错误。

可以把 `main` 理解为正常通车的主路，把功能分支理解为施工岔路。新功能先在岔路上开发和测试，确认无误后通过 `merge` 合并回主路；方案失败时可以放弃该分支，不影响稳定主线。

原来理解不准确的地方：

- 分支不能消灭错误，只能隔离修改
- 直接修改 `main` 并非不可恢复，但会增加稳定主线的风险
- 完成功能后需要合并分支，不只是切换回 `main`

### git push

原来以为 `git push` 会上传暂存区或所有本地文件。实际上，`git push` 只会上传本地仓库中已经 `commit` 的提交；没有提交的修改不会上传。

```text
git add：把要提交的修改放入暂存区
git commit：在本地仓库创建版本快照
git push：把本地提交上传到远程仓库
```

## 二、反向工程别人的代码

今天阅读了 `microsoft/Web-Dev-For-Beginners` 中植物拖拽功能的 `script.js`。没有从第一行逐字阅读，而是沿着一个用户行为追踪完整功能流。

### 用户故事

用户按住一株植物并移动鼠标，植物跟随移动；松开鼠标后，植物停止移动。

### 功能流

```text
找到植物元素
→ 调用 dragElement 为植物添加拖拽能力
→ 注册 pointerdown 事件
→ 按下时记录初始鼠标坐标
→ 移动时计算前后坐标差
→ 更新植物的 top 和 left
→ 保存当前坐标供下一次移动计算
→ 松开时停止监听移动事件
```

### 读懂的设计

14 株植物是不同的 DOM 元素，但使用相同的拖拽逻辑。作者将通用逻辑写进 `dragElement()`，再把每株植物分别传入，避免复制 14 份相同代码。

### 新发现的知识漏洞

浏览器坐标原点在左上角：

- X 增大表示向右
- Y 增大表示向下
- `top` 减小表示向上

这与常见数学坐标系的 Y 轴方向相反，阅读页面定位、Canvas 或游戏代码时需要特别注意。

## 四、Python 语法基础

确认本机 Python 版本为 `Python 3.13.11`，在交互式解释器中边输入边练习。

### 输出、变量与输入

- `print()` 可以显示内容；`#` 后面是注释，Python 不会执行注释。
- 变量可以保存数据，例如 `course = "Python"`，之后用 `print(course)` 读取。
- 引号内是文本：`"3" + "2"` 得到 `"32"`；不带引号的数字可以计算：`3 + 2` 得到 `5`。
- `input()` 收到的内容默认是文本；用 `int()` 转成整数后才能按数字计算。练习中输入 `3`，计算 `number + 1` 得到 `4`。

### 条件判断

练习了 `if / elif / else`，并写出成绩判断：`60–100` 为及格，`0–59` 为不及格，其他范围为无效成绩。输入 `70` 后程序显示“你的成绩及格”。

要点：`else` 处理前面条件都不成立的情况；因此当代码还检查分数范围时，最后一类应提示“成绩无效”，不能也显示“不合格”。

### 循环

- `for i in range(3)` 打印 `0、1、2`；`range` 从起始值开始，但不包含结束值。
- `while` 在条件为真时重复执行。计数变量必须在循环中更新，否则条件一直成立会形成死循环。
- 一次遗漏计数更新导致循环无法结束；停止后重新运行，并加入 `count += 1`，成功打印 `1、2、3` 后退出。
- `break` 立即结束循环；`continue` 跳过当前这一轮。练习结果分别确认了两者的区别。

### 函数

- 用 `def` 定义函数；函数体通过缩进标记。
- 参数让函数接收不同输入，例如 `greet(name)`；调用 `greet("小明")` 后显示“你好，小明”。
- `print()` 负责显示；`return` 把结果交回调用处，之后可以保存和继续使用。练习 `add(1, 3)` 并把结果存入 `total`，`print(total)` 显示 `4`。
